# Skenario Uji Milestone Proyek 6 — Perpustakaan Lentera AYP

**NPM:** 25430016  |  **P:** 8  |  **Basis data:** `perpus_016`
**Berkas terkait:** `p05_ddl_25430016.sql`, `p06_data_25430016.sql`

## 1. Ringkasan

Dokumen ini memuat **12 skenario uji**: 3 positif (data benar harus diterima) dan 9 negatif (data salah harus ditolak). Satu skenario negatif, **UJ-12**, sengaja dirancang **GAGAL** karena aturannya belum dapat dijaga server. UJ-12 dicatat sebagai **utang desain untuk Modul 14** (Bagian 4).

Setiap skenario merujuk kode aturan bisnis **AB-xx** (`p02_kebutuhan_data_25430016.md`) atau nama constraint/trigger pada `p05_ddl_25430016.sql`.

## 2. Cara Menjalankan

1. Bangun ulang dari basis data kosong: jalankan `p05_ddl_25430016.sql`, lalu `p06_data_25430016.sql`.
2. Buka klien `mysql` pada basis data `perpus_016`, lalu jalankan blok SQL tiap skenario satu per satu.
3. Semua skenario positif dan skenario yang menyentuh data dibungkus `START TRANSACTION ... ROLLBACK`. Isi basis data tidak berubah setelah uji, sehingga urutan uji bebas dan hasilnya dapat diulang tanpa membangun ulang.
4. Salin pesan yang tampil di layar ke kolom **Hasil nyata** pada Tabel 3, lalu isi **Status**: `LULUS` jika hasil nyata sama dengan harapan, `GAGAL` jika berbeda.

Kode galat pada kolom Harapan memakai **MariaDB (XAMPP)**. Pada MySQL 8.0.16+, galat `CHECK` bernomor **3819** (bukan 4025); galat lainnya sama.

| Galat | Arti |
|---|---|
| 1644 (45000) | `SIGNAL` dari trigger aturan bisnis |
| 1062 (23000) | Duplikat pada PRIMARY KEY atau UNIQUE |
| 1452 (23000) | Foreign key gagal saat mengisi tabel anak |
| 4025 (23000) | Constraint `CHECK` dilanggar (MySQL: 3819) |

**Data yang dipakai uji** (dari `p06_data_25430016.sql`):

|---|---|
| `A001` | Anggota Aktif |

## 4. Skrip Pengujian

### UJ-01 — Peminjaman oleh anggota Aktif diterima (positif)

Aturan: AB-02 (anggota Aktif), AB-03 (eksemplar Tersedia), AB-05 (data transaksi lengkap).

```sql
START TRANSACTION;

INSERT INTO peminjaman (id_peminjaman, nomor_anggota, id_petugas, tanggal_pinjam, tanggal_jatuh_tempo)
VALUES ('PJM-20261031-001', 'A001', 'PT001', '2026-10-31', '2026-11-07');

INSERT INTO detail_peminjaman (id_peminjaman, id_eksemplar)
VALUES ('PJM-20261031-001', 'E037');

-- Harapan: status_eksemplar = 'Dipinjam' (diatur trg_detail_ai)
SELECT id_eksemplar, status_eksemplar FROM eksemplar WHERE id_eksemplar = 'E037';

ROLLBACK;
```

Harapan: kedua INSERT `Query OK, 1 row affected`; SELECT menampilkan `E037 | Dipinjam`.

### UJ-03 — Pengembalian terlambat 2 hari beserta denda diterima (positif)

Aturan: AB-06 (pengembalian merujuk detail yang valid), AB-07 (keterlambatan dari tanggal kembali dan jatuh tempo), AB-08 (Rp8.000 per hari).

```sql
START TRANSACTION;

INSERT INTO pengembalian (id_pengembalian, id_peminjaman, id_eksemplar, id_petugas, tanggal_pengembalian)
VALUES ('RET-20261031-001', 'PJM-20261022-002', 'E017', 'PT001', '2026-10-31');

-- jatuh tempo 2026-10-29, kembali 2026-10-31 -> terlambat 2 hari -> 2 x 8000 = 16000
INSERT INTO denda (id_denda, id_pengembalian, hari_terlambat, nominal_denda, status_bayar)
VALUES ('D018', 'RET-20261031-001', 2, 16000, 'Belum Dibayar');

SELECT d.status_detail, e.status_eksemplar, n.hari_terlambat, n.nominal_denda
FROM detail_peminjaman d
JOIN eksemplar e ON e.id_eksemplar = d.id_eksemplar
JOIN pengembalian g ON g.id_peminjaman = d.id_peminjaman AND g.id_eksemplar = d.id_eksemplar
JOIN denda n ON n.id_pengembalian = g.id_pengembalian
WHERE d.id_peminjaman = 'PJM-20261022-002' AND d.id_eksemplar = 'E017';

ROLLBACK;
```

Harapan: semua INSERT diterima; SELECT menampilkan `Dikembalikan | Tersedia | 2 | 16000`.

### UJ-12 — Peminjaman tanpa satu pun eksemplar (uji gagal / utang desain)

Aturan: AB-04 dan AB-05. Batas atas 10 eksemplar sudah dijaga (UJ-06), tetapi batas bawah (minimal satu eksemplar per transaksi) belum.

```sql
START TRANSACTION;

-- Header peminjaman tanpa detail apa pun
INSERT INTO peminjaman (id_peminjaman, nomor_anggota, id_petugas, tanggal_pinjam, tanggal_jatuh_tempo)
VALUES ('PJM-20261031-001', 'A001', 'PT001', '2026-10-31', '2026-11-07');

-- Bukti: transaksi tersimpan dengan 0 detail
SELECT p.id_peminjaman, p.status_peminjaman, COUNT(d.id_eksemplar) AS jumlah_detail
FROM peminjaman p
LEFT JOIN detail_peminjaman d ON d.id_peminjaman = p.id_peminjaman
WHERE p.id_peminjaman = 'PJM-20261031-001'
GROUP BY p.id_peminjaman, p.status_peminjaman;

ROLLBACK;
```

Harapan (seharusnya): INSERT ditolak karena peminjaman wajib memuat minimal satu eksemplar.
Diperkirakan terjadi: `Query OK, 1 row affected`; SELECT menampilkan `PJM-20261031-001 | Berlangsung | 0`.
**Status: GAGAL** (aturan belum dapat dijaga server).

## 5. Utang Desain untuk Modul 14

| Butir | Isi |
|---|---|
| Kode utang | **UD-01** (dari uji **UJ-12**) |
| Aturan yang belum dijaga | Satu transaksi peminjaman wajib memuat **minimal 1 eksemplar** (PB-03: transaksi mencatat eksemplar yang dipinjam). Berkaitan dengan AB-04 (batas atas, sudah dijaga) dan AB-05 (kelengkapan transaksi). |
| Bukti | UJ-12: baris `peminjaman` tersimpan dengan 0 baris `detail_peminjaman`. |
| Mengapa constraint tidak cukup | `PRIMARY KEY`, `FOREIGN KEY`, `UNIQUE`, dan `CHECK` hanya memeriksa satu baris atau satu hubungan ke baris induk. Aturan "induk harus punya anak" melibatkan baris di tabel lain yang belum ada saat header dimasukkan. Detail baru dapat dimasukkan setelah header karena FK `fk_detail_peminjaman` mensyaratkan header ada lebih dulu. Karena itu trigger `BEFORE INSERT` pada `peminjaman` tidak dapat menolaknya. |
| Akibat jika dibiarkan | Header kosong menumpuk berstatus `Berlangsung` selamanya. Jika detail ke-11 ditolak (UJ-06) pada mode autocommit, 10 detail pertama tetap tersimpan, sehingga peminjaman hanya selesai sebagian. |
| Rencana pelunasan (Modul 14) | Bungkus satu peminjaman sebagai **satu transaksi**: `START TRANSACTION` → `INSERT peminjaman` → `INSERT detail_peminjaman` (1 sampai 10 baris) → periksa `SELECT COUNT(*)` pada detail → jika 0 atau ada galat, `ROLLBACK`; jika 1 sampai 10, `COMMIT`. Pemetaan: pemeriksaan jumlah → AB-04/AB-05, status eksemplar → AB-03, anggota Aktif → AB-02. |
| Catatan dokumen | "Minimal 1 eksemplar" belum tertulis eksplisit pada AB-01 sampai AB-10. Disarankan menambahkannya sebagai AB-11 pada dokumen kebutuhan data agar uji ini merujuk aturan yang tertulis. |

**Temuan tambahan (hasil membaca `p05_ddl_25430016.sql`, belum diuji):** trigger AB-02, AB-03, dan AB-04 hanya aktif pada `BEFORE INSERT`. Perintah `UPDATE` yang memindahkan `nomor_anggota`, `id_peminjaman`, atau `status_eksemplar` berpotensi melewati aturan tersebut. Temuan ini layak dipertimbangkan sebagai utang desain tambahan pada Modul 14.

## 6. Pernyataan Keterulangan

- `p05_ddl_25430016.sql` memulai dengan `DROP TABLE IF EXISTS` untuk semua tabel, sedangkan `p06_data_25430016.sql` tidak memakai `AUTO_INCREMENT`. Semua kunci berupa kode alami (`A001`, `E037`, `PJM-20261005-001`, dan seterusnya).
- Hasil pembangunan ulang selalu sama: petugas 6, anggota 12, buku 12, eksemplar 49, peminjaman 80, detail_peminjaman 95, pengembalian 69, denda 17.
- Peminjaman tersebar pada 8 tanggal (2026-10-05, 06, 12, 13, 19, 20, 22, 26).
- Skenario uji tidak mengubah isi basis data karena memakai `ROLLBACK` atau memang ditolak.
